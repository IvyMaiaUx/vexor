# VEXOR — Etapa 9.6 — Matriz de Compatibilidade Frontend vs Backend Supabase

Este documento mapeia cada funcionalidade do painel administrativo (`/admin`) para as tabelas, views, policies RLS e RPCs oficiais do Supabase.

| Funcionalidade / Módulo | Origem no Backend Supabase | Nível de Acesso (App + DB) | Comportamento / Limitações Reais |
|---|---|---|---|
| **Dashboard (`/admin`)** — Contagens de usuários, recursos, tópicos, posts, denúncias | `SELECT` com `count: "exact"` em `profiles`, `resources`, `topics`, `posts`, `reports` | App: `moderator` \| DB: `is_moderator()` | Totalizações reais via Supabase. `pendingResearch` não tem tabela no banco (retorna `0` com indicação explícita de ausência de tabela). |
| **Dashboard (`/admin`)** — Eventos recentes de auditoria | `SELECT` em `audit_logs` (ordenado por `created_at desc`, limite 5) | App: `admin` \| DB: `is_admin()` | Para `moderator` não-admin, RLS restringe `audit_logs`; a UI exibe estado de acesso restrito/indisponível sem erro fatal nem dados fictícios. |
| **Usuários (`/admin/users`)** — Listagem, busca, filtros e resumo | `SELECT` em `profiles` (`id, username, display_name, avatar_url, bio, interests, github_url, linkedin_url, preferred_language, role, is_suspended, created_at`) | App: `admin` \| DB: `is_moderator()` | Campos como `email` (privado em `auth.users`) e `lastActivityAt` não existem em `public.profiles` e não são expostos. |
| **Usuários (`/admin/users`)** — Alterar papel (`member` / `moderator` / `admin`) | `rpc("admin_set_user_role", { p_user_id, p_role })` | App: `admin` \| DB: `is_admin()` | Impede auto-rebaixamento e rebaixamento do último admin ativo no banco (`42501` / `P0002` / `22023`). Auditoria gravada automaticamente pela RPC. |
| **Usuários (`/admin/users`)** — Suspender / Reativar usuário | `rpc("admin_set_user_suspension", { p_user_id, p_suspended, p_reason })` | App: `admin` \| DB: `is_admin()` | Exige justificativa para suspensão; impede auto-suspensão e suspensão do último admin ativo. Auditoria gravada automaticamente pela RPC. |
| **Moderação (`/admin/moderation`)** — Fila de Recursos | `SELECT` em `resources` (todos os status) + join/lookup de `profiles` para autor | App: `moderator` \| DB: `is_moderator()` | Ações suportadas pela RPC `moderate_resource`: `approve` (`approved`), `reject` (`rejected`, exige motivo), `archive` (`archived`). |
| **Moderação (`/admin/moderation`)** — Fila de Tópicos do Fórum | `SELECT` em `topics` (todos os status) + lookup de `profiles` | App: `moderator` \| DB: `is_moderator()` | Ações suportadas pela RPC `moderate_topic`: `hide`, `unhide`, `delete`, `pin`, `unpin`, `lock`, `unlock` (`hide`/`delete` exigem motivo). |
| **Moderação (`/admin/moderation`)** — Fila de Posts do Fórum | `SELECT` em `posts` (todos os status) + lookup de `profiles` e `topics` | App: `moderator` \| DB: `is_moderator()` | Ações suportadas pela RPC `moderate_post`: `hide`, `unhide`, `delete` (`hide`/`delete` exigem motivo). |
| **Moderação (`/admin/moderation`)** — Fila de Cybercrime Research | Sem tabela no schema PostgreSQL atual | N/A | Não inventa itens simulados; retorna fila vazia com indicação explícita de módulo ainda sem persistência no banco. |
| **Moderação (`/admin/moderation`)** — Ações `escalate` / `request_revision` | Não existem nas RPCs oficiais | N/A | Bloqueadas explicitamente na validação com mensagem clara de ação não suportada pelo backend atual (sem gravação fictícia). |
| **Denúncias (`/admin/reports`)** — Listagem e filtros | `SELECT` em `reports` + lookup de `profiles` (`reporter_id`, `handled_by`) | App: `moderator` \| DB: `is_moderator()` | Suporta filtros por `status`, `reason` e `target_type`. |
| **Denúncias (`/admin/reports`)** — Análise / Resolução / Descarte | `rpc("resolve_report", { p_report_id, p_status, p_note })` | App: `moderator` \| DB: `is_moderator()` | Aceita apenas `'reviewing' | 'resolved' | 'dismissed'`. Rejeita `'open'` conforme constraint da RPC. Auditoria gravada automaticamente pela RPC. |
| **Auditoria (`/admin/audit`)** — Listagem, filtros, detalhe, resumo e CSV | `SELECT` em `audit_logs` + lookup opcional de `profiles` (`actor_id`) | App: `admin` \| DB: `is_admin()` | Somente leitura. Nenhuma escrita de auditoria é feita pelo cliente; exportação CSV mantém proteção contra formula injection. |
